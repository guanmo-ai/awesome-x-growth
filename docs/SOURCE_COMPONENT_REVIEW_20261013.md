## 对五条意见逐项复核

| Grok 意见 | 本地复核 | 处理 |
| --- | --- | --- |
| 非 UTC 日期提前停止；给出 `2025-10-13 00:30 -0400` 例子 | 指定例子不成立：原始日期与 UTC 日期都为 10 月 13 日。但 `00:30 +0900` 的 UTC 日期为前一天，原来的本地日历提取确有边界风险 | 驳回错误例子；UTC 规范化与取消单页日期提前结束已修，正确边界有回归 |
| 转推被归到时间线作者 | `via.author` 原本代表发现入口，正式回源作者由 `normalize` 重新核对，不等于已收录错误作者；字段确实容易被误读 | 保留 `timelineOwner` 和原帖 URL 的 `authorHint`，列表标 `originalityVerified=false`；回源继续核对真实作者 |
| 同 ID 不同 handle 只保留先出现的链接 | 可以复现线索信息丢失；账号改名或错误别名尚不能只凭 URL 判断谁是真作者 | 去重仍按 ID，保留 `urlVariants` 与 `authorHintConflict`，真实作者以回源结果为准 |
| 导入的 `via` 对象使作者分页失败 | 导入 JSON 的来源为对象，作者发现追加时确会报错，且旧计数代码假设每个来源都有作者字段 | 加载时规范化为来源数组，保留原来源并用入口字段计数；合并后可继续并到末端 |
| 同目录 leads 与 records 重复产生作者覆盖记录 | 可以复现，两条输入路径共享同一作者进度 | 按进度文件去重；同时间窗的全局汇总另按作者与最新扫描计算，有重复输入回归 |

三项线索合并或统计缺陷得到修正，一项语义歧义已澄清，一项具体日期复现例子被驳回。未将全部模型意见直接升级成事实。Grok 提到的两个主题词表不是本轮阻塞缺陷：展示主题与数据完整主题原本就有不同用途。
